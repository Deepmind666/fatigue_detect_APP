## 1. 总览与阅读地图
- 项目由两部分组成：
  - Android 应用（点单、统计、与硬件通信）
  - STM32 硬件控制程序（解析指令、控制电机/阀门/称重等）
- 推荐阅读顺序：
  1) 目录结构 → 2) Android 架构与流程 → 3) 硬件交互与协议 → 4) 依赖与配置 → 5) 排障要点

## 3. Android 架构与流程

### 3.1 架构风格
- 应用采用 MVVM + Jetpack Compose：
  - UI 层（Compose Screen）展示状态与触发事件
  - ViewModel 负责业务状态管理、与 Repository/硬件交互
  - Repository 负责数据读写（Room）、领域聚合
  - HardwareManager 负责与 STM32 的串口通信与协议解析
- 关键优点：UI 与业务解耦、状态单向流动、可测试性更好

### 3.2 启动与权限
- MainActivity 负责：
  - 运行时权限申请（相机、媒体/存储，按 Android 版本区分）
  - 注册 USB 权限广播（统一 action），收到授权后触发硬件重新连接
  - setContent 载入 AppNavigation，进入 Compose 导航框架
- onStart() 生命周期中主动调用 HardwareManager.connect() 发起连接（若无权限则请求授权并等待回调）。

### 3.3 UI 导航与主要界面
- AppNavigation 组织各 Screen：饮品菜单、统计、管理员等。
- 典型用户路径：主界面选择饮品 → 弹出“自定义”对话框（杯型、冰度）→ 下单 → 制作 → 完成/异常处理 → 统计页面查看经营数据。
- 说明书中已插入“方案B（含泳道）”的端到端流程图（docs/images/流程图-门店点单-制作-交付-含泳道.svg）。

### 3.4 ViewModel 层（以 DrinkMenuViewModel 为例）
- 负责状态聚合：菜单、连接状态、错误提示、重量变化对话框、图片选取等。
- 下单流程要点：
  - 未连接硬件时仍允许下单：先本地入库并提示“正在尝试重连”，然后走“离线模拟完成”（避免统计为零）。
  - 已连接硬件：调用 HardwareManager.makeJuice() 发送指令；若发送失败则将订单标记为 FAILED。
  - 兜底机制：20 秒未收到硬件回调，自动将订单标记为 COMPLETED 计入统计（保证经营看板可用）。
  - 使用 pendingOrderIds 队列按顺序对应“下单 → 硬件完成回调”，避免错位。
- 异常处理：
  - 设置重量异常监听器，出现“继续/重启”选择；选择后调用 sendContinueCommand()/sendRestartCommand()。

### 3.5 数据层（Room + Repository）
- database：
  - AppDatabase/DAO/实体（Recipe、Order 等）
  - Converters 等工具类
- repository：
  - RecipeRepository：配方的增删改查、预置数据注入
  - OrderRepository：订单入库、状态更新、统计刷新通知

### 3.6 硬件交互（HardwareManager）
- 设备发现与权限：
  - 枚举 UsbSerialProber 可用驱动，记录 VID/PID（常见 CH340/CP2102），无权限时请求 USB 权限并等待广播回调。
- 串口参数：9600 8N1（与旧版保持一致）。
- 帧解析策略：
  - 帧边界：以 0xFF 起始、0xFE 结束，按 7 字节帧解析，采用 frameBuffer 解决粘包/分包。
  - 重量异常帧：cmd=0x09，字节2为 severity，字节3-4为值（lo/hi 组合）。收到后在主线程回调 onWeightAnomalyListener。
  - 完成/失败：status=0xAA（成功）/0xAC（失败），在主线程回调 onOrderCompletionListener。
- 并发与健壮性：
  - portLock/writeLock 保障端口列表与写入互斥
  - IOManager 监听串口数据回调 onNewData()
  - reconnectJob 自动重连（如需要）
- 对外 API：connect()/disconnect()/makeJuice()/sendContinueCommand()/sendRestartCommand()，以及 setOnStatusListener()/setOnWeightAnomalyListener()/setOnOrderCompletionListener()。

## 4. STM32 侧概览（根据现有文档）
- 职责：
  - 解析上位机下发帧（FF ... FE），执行动作：配方出液、阀门、电机、称重读取等。
  - 上报实时状态：制作成功/失败，重量异常等事件。
- 约束：
  - 指令与状态码已标准化，便于 Android 端可靠解析与容错。

> 详细 MCU 代码不在本仓库；如需扩展，请保持协议兼容（见下节）。

---

## 5. 通信协议（要点）
- 帧格式：
  - 起始 0xFF，结束 0xFE，长度固定 7 字节（当前实现）。
  - [1] 命令码 cmd；[2] 状态/参数1；[3..4] 参数2（lo/hi）；[5] 保留；[6] 0xFE。
- 上行（STM32 → Android）：
  - 重量异常：cmd=0x09，severity={1/2/3..}，value=lo/hi 组合。
  - 订单完成/失败回调：status=0xAA（成功）/0xAC（失败）。
- 下行（Android → STM32）：
  - makeJuice/继续/重启 等通过 buildFrame()/sendCommand() 构造与发送（9600,8N1）。

> 若协议需扩展，建议保留 FF/FE 边界与长度校验；新增 cmd 不影响既有解析分支。

## 7. 日志与排障
- DebugLogger：统一收敛关键事件（连接、下发、回调、异常等），减少干扰的 Toast；必要时提示。
- 导出日志：在 MainActivity 的根视图长按，触发 FileProvider 分享日志文本，便于现场排障。
- 常见问题：
  - 未检测到设备：检查数据线、转接头、USB 权限授权是否完成。
  - 发送指令失败：查看串口是否被占用、波特率参数是否一致、权限是否丢失。
  - 长时间无回调：ViewModel 有 20s 兜底自动完成，先保障统计可用，之后分析串口链路。

## 8. 开发与扩展建议
- 新增饮品：通过 RecipeRepository/Room 新增实体，UI 自动订阅并展示；注意各杯型的配方参数与库存扣减。
- 新增硬件/协议：在 HardwareManager 中新增 cmd 分支与发送方法，保持 0xFF/0xFE 帧规则；在 ViewModel 添加状态流与 UI 显示。
- 统计面板扩展：分品类/时段/门店等维度，注意空数据与异常保护（已在 2.5.6 预留）。
